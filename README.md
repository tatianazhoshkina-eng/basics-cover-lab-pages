# Basics cover constructor

Рабочий production-конструктор обложек курса Basics. Для команды используется опубликованный GitHub Pages; `basics_cover_constructor.html` остаётся локальной резервной копией.

## Что можно менять независимо

- 7 типов материалов: утренняя и основная тренировки, техника, кофе-ток, подкаст, практика и шапка курса;
- одно крупное точное название материала без дублирования;
- независимые слои фотографии, цветового поля, заголовка, логотипа и служебной строки;
- 4 переноса заголовка и отдельные координаты/размеры;
- прямой двухцветный локап `#sekta basics.` без курсива;
- белая, голубая, сиреневая и navy-плашки с жёсткой границей;
- 4 цвета надписи: тёмно-синий, чёрный, сиреневый и белый;
- 57 фотографий с фильтрами и поиском;
- первый extended master 1792×720 с 20% дополнительного фона слева и справа;
- масштаб фотографии 100–220%, сильное панорамирование X/Y и индикатор потери качества при чрезмерном увеличении;
- независимые выключатели недели, дня и длительности;
- два синхронных режима просмотра: крупная обложка и реальная карточка внутри страницы курса;
- автоматическая оценка фактического кегля в карточке: «читается», «на границе» или «мелковато».
- адаптивный интерфейс: на обычной ширине фотобанк открывается отдельной кнопкой и не сжимает рабочий холст;
- производственный реестр из 46 мастер-слотов, покрывающих 146 замен в курсе;
- контроль готовности по семействам и расширенный backlog следующих пакетов;
- перенос проекта между браузерами через JSON;
- единый ZIP для загружающего агента: PNG, `manifest.json`, `manifest.csv`, инструкция и список недостающих слотов.

## Рабочий процесс

1. Выберите производственный слот; конструктор подставит точное название, неделю и назначение файла.
2. Подберите композицию и фотографию.
3. Переключитесь на «На странице курса»: текущая обложка вставляется в настоящий скриншот кабинета вместе с кнопкой воспроизведения.
4. Проверьте индикатор фактического кегля и маленькое превью: текст должен читаться в масштабе карточки курса.
5. Нажмите «Сохранить вариант»: слот станет готовым в реестре.
6. Для передачи работы другому участнику экспортируйте JSON проекта; на другом устройстве импортируйте его.
7. После заполнения пакета нажмите «ZIP для агента». Архив содержит файлы с финальными именами и точную карту загрузки по неделям и дням.

GitHub Pages — статический сайт, поэтому сохранённые варианты хранятся в `localStorage` конкретного браузера и не синхронизируются автоматически. Для смены устройства или передачи смены используйте «Экспорт проекта» и «Импорт проекта». Если пакет неполный, ZIP содержит `MISSING_SLOTS.md`; агент не должен публиковать такой пакет без подтверждения ответственного.

Подробная сверка с брендбуком находится в `basics_cover_system_audit.md`.
